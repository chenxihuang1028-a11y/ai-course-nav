**01:45–04:05 为什么要开这门课**
核心论点:现在的研究者离底层技术越来越远——8年前大家自己训模型,6年前至少还会下载BERT这类模型做微调,现在很多人只是在调用一个闭源模型的API。这不完全是坏事(抽象层让大家能做更多事),但这些抽象是"漏"的,你不真正理解字符串进、字符串出中间发生了什么。要做基础研究,必须能拆开整个技术栈——数据、系统、模型一起设计。这门课的哲学是:要理解,就得自己搭一遍。

**04:05–05:14 现实的难题**
GPT-4传闻1.8万亿参数,训练成本1亿美金;xAI在建20万张H100的集群;行业4年内投入号称超过5000亿美金。而且没有任何公开细节——GPT-4的报告明确说"出于竞争考虑和安全限制,不披露细节"。前沿模型已经是普通人碰不到的规模,这门课不可能让你训一个自己的GPT-4,只能训小模型。

**05:14–07:05 小模型的局限性(为什么"研究不能光看小规模现象")**
举了两个例子:
1. Attention层和MLP层的FLOPs占比,在小模型里差不多,但到175B参数规模MLP会主导——如果你在小规模死磕优化attention,可能优化错了方向。
2. "涌现能力"现象(引用Jason Wei 2022年论文):随着训练FLOPs增加,某些任务的准确率长期没反应,然后突然涌现(比如上下文学习能力)。如果只在小规模实验,会误以为"这方法根本不work",其实是还没scale到位。

**07:05–08:43 这门课能教你的三种知识**
1. **机制(mechanics)**——能教:Transformer怎么实现、模型并行怎么用好GPU
2. **心态(mindset)**——能教但比较微妙:把硬件榨干、认真对待scaling,这是OpenAI真正跑出下一代模型的关键心态,而不是具体某个组件
3. **直觉(intuition)**——只能部分教:哪些数据/建模决策在大规模下有效,因为小规模有效的架构和数据集不一定在大规模依然有效

**08:43–09:32 有些事就是没有解释**
举SwiGLU论文(Shazeer)的例子——论文结论里作者诚实写道,效果好但"除了这是神的恩典之外,我们无法解释"。这就是这个领域理解的现状,很多设计是靠实验试出来的,不是靠推导。

**09:32–11:42 "苦涩的教训"(Bitter Lesson)的正确理解**
常见误解:苦涩的教训=规模就是一切,算法不重要,砸钱堆算力就行。Percy认为正确解读是"大规模下的算法才重要"——模型效果本质是效率×投入资源。而且规模越大,效率越重要(烧几亿美金的实验容不得浪费,不像在自己集群上跑错了可以重来)。引用一篇2020年OpenAI论文:2012-2019年,把ImageNet训到同等准确率所需的算力,算法效率提升了44倍,比摩尔定律还快。结论:算法确实重要。

**11:42–12:12 这门课的核心提问**
在给定的算力和数据预算下,能训出的最好模型是什么?这个问题在任何规模下都成立,因为问的是"每单位资源的准确率"。研究者的目标是提升算法效率,不是简单砸资源。

**12:12–17:03 语言模型简史(略讲)**
Shannon用语言模型估计英语的信息熵 → 早期NLP里作为机器翻译/语音识别的组件 → 2007年Google已经在2万亿token上训5-gram模型(比GPT-3的token数还多,但N-gram模型没有涌现能力)→ 2010年代深度学习的关键拼图逐个到位:Bengio 2003第一个神经语言模型、seq2seq(Ilya等)、Adam优化器、注意力机制→2017年Transformer论文、MoE、模型并行研究(能训千亿参数但没长时间训)→基础模型思路兴起(ELMo/BERT/T5)→OpenAI把这些拼图工程化+认真做scaling law,催生GPT-2/GPT-3→闭源模型之外,开源模型线(EleutherAI、Meta早期尝试、BLOOM、Meta/阿里/DeepSeek/AI2等)→现在:OpenAI/Anthropic/xAI/Google/Meta/DeepSeek/阿里/腾讯等群雄逐鹿。这门课的目标是把这些拼图重新讲一遍,并尽量向前沿模型的最佳实践靠拢。

**27:43–29:09 Unit 1之一:Tokenizer**

**31:35–32:20 Unit 1之三:训练**

**32:20–33:37 Assignment 1详情**

**33:37–34:15 Unit 2引入:Systems**
覆盖kernels、并行、推理三块,目标是怎么把硬件榨干。

**34:15–36:07 Kernels**
GPU结构讲解(芯片上的计算单元 vs 片外显存),核心瓶颈是数据搬运成本,不是算力本身。类比:显存像仓库,计算像工厂。课程会用Triton(OpenAI开发的工具)写kernel,做fusion、tiling这类优化。

**36:07–37:11 多GPU并行**
GPU之间通过NVSwitch/NVLink互联,同样面临数据搬运问题,规模更大。会讲数据并行、张量并行等技术。

**37:11–39:49 推理(Inference)**
去年没讲,今年新增。推理成本正在全面超过训练成本,因为训练是一次性的,推理成本随使用量线性增长。分两个阶段:prefill(处理prompt,可并行,compute-bound)和decode(逐token生成,memory-bound,更难榨干GPU利用率)。会讲投机解码(speculative decoding)等加速技术。

**39:49–40:50 Assignment 2详情**
实现一个kernel、实现并行(数据并行 + 简化版FSDP)。强调要养成"跑benchmark和profile"的习惯,不然实现了东西也不知道瓶颈在哪。

**40:50–43:05 Unit 3:Scaling Laws**
核心问题:给定FLOPs预算,模型该多大?模型越大能训的数据越少,越小能训的数据越多。介绍Chinchilla Optimal——OpenAI和DeepMind的一系列论文研究出的经验法则:模型参数量N,训练token数大约是20N。这条曲线拟合出来后异常线性。但这条法则没考虑推理成本,只回答"怎么训出最好的模型"。

**43:05–44:48 Assignment 3详情**
提供一个"训练API",输入超参数(架构、batch size等)返回loss。在给定的FLOPs预算下,自己设计实验、拟合scaling law、预测大规模下该用的超参数。排行榜是"给定FLOPs预算最小化loss"。

**44:48–45:57 Unit 4引入:Data**
核心问题:你想让这个模型做什么?这基本上完全由数据决定——训多语言数据就有多语言能力,训代码就有代码能力。

**45:57–46:43 评测(Evaluation)**
perplexity、MMLU这类标准化测试、指令遵循类生成怎么评、test-time ensemble/思维链对评测的影响,以及整个系统(不只是语言模型本身,常常被接入agent系统)的评测。

**46:43–50:00 数据整理(Data Curation)**
纠正一个常见误解:"我们是在互联网上训练模型"——数据不会凭空掉下来,必须主动获取。现场展示了Common Crawl的原始抓取样本,大部分是垃圾内容/spam站点。数据处理链路:爬取→HTML转文本(有损过程)→过滤(用分类器去除低质和有害内容)→去重。也提到法律问题——现在前沿模型很多要花钱买数据,因为公开可用的数据对前沿性能来说其实不够用。

**50:00–50:24 Assignment 4详情**
拿到原始Common Crawl数据,训分类器做过滤、去重,排行榜是给定token预算最小化perplexity。

**50:24–52:05 Unit 5引入:Alignment**
预训练完只得到一个"补全下一个token"的base模型,需要对齐才有用。对齐要解决三件事:指令遵循(补全下一个token不等于遵循指令)、生成风格控制(长短、要点式、语气)、安全性(拒答有害请求)。

**52:05–53:04 SFT(监督微调)**
收集一批"用户-助手"配对数据做监督学习,本质和预训练类似(只是最大化文本概率),base模型已经有潜力,少量样本(论文显示上千条)就能激发出指令遵循能力。

**53:04–55:03 从反馈中学习**
更多SFT数据成本很高(需要人工标注)。介绍两类更轻量的监督信号:偏好数据(同一个prompt生成A/B两个回复,人来判断哪个更好)和verifier(数学/代码这类有形式化验证器的领域,或者用另一个模型当learned verifier打分)。算法层面:PPO是最早用在指令微调上的强化学习算法;如果只有偏好数据,DPO更简单好用;如果是verifier数据就得上真正的RL,课程会讲GRPO(DeepSeek提出,去掉了value function,比PPO更高效)。

**55:03–55:09 Assignment 5详情**

**56:05–58:53 全课程回顾:一切都是效率**
数据处理(过滤是为了不浪费算力在垃圾数据上)、tokenization(字节级模型更优雅但当前架构下效率太低)、模型架构(设计决策基本都是效率驱动)、只训一个epoch(说明现在是"算力紧、数据多"的状态)、scaling law(用更少算力找到超参数)、对齐(投入对齐资源后,可以用更小的base模型达到效果)——都是效率这条主线串起来的。

**1:00:24–1:01:22 正式进入Tokenization**
推荐Andrej Karpathy关于tokenization的视频(这门课很多灵感来自于他"从零构建"系列)。Tokenization就是把Unicode字符串转成整数序列(每个整数是一个token),需要一个能双向转换(编码/解码)的方案。

**1:01:22–1:04:59 用在线工具演示tokenizer行为**
现场演示一个tokenizer可视化网站,输入"hello"观察分词结果。几个关键观察:空格是token的一部分(不像经典NLP里空格直接消失);按惯例空格通常在token前面;"hello"和" hello"(带前导空格)是完全不同的token,容易让人意外;数字被从左到右切成不规则的段,不是按千位分组这种语义方式。

**1:04:59–1:05:12 GPT-2 tokenizer实测**
用GPT-2的tokenizer做编码解码往返验证,并计算压缩率(每个token代表的字节数)=1.6字节/token。

**1:05:12–1:07:09 尝试1:字符级tokenization**
把每个Unicode字符映射为一个code point(比如A=97)。问题:某些code point数值巨大(比如emoji),词表利用率很差——给每个字符分配一个槽位,但字符出现频率差异巨大,压缩率只有1.5左右。

**1:07:09–1:09:03 尝试2:字节级tokenization**
把字符串转成UTF-8字节序列,词表只有256个可能值,非常小且均匀。问题:序列长度爆炸,压缩率是1(一字节一个token),而Attention的计算量对序列长度是平方级的,序列一长效率就崩了。

**1:09:03–1:11:02 尝试3:词级tokenization**
用正则表达式把字符串切成"词"(GPT-2用了专门的正则做预分词)。问题:词表大小不可控——遇到没见过的词就会分配UNK token,如果不小心处理perplexity计算会直接出问题。

**1:11:02–1:12:01 BPE登场**
BPE(Byte Pair Encoding)是Philip Gage在1994年为数据压缩发明的老算法,后来被引入神经机器翻译(取代词级tokenization,解决UNK问题),GPT-2把它带入了语言模型时代。

**1:12:01–1:12:43 BPE的核心思路**
不预设怎么切分,而是在原始文本上"训练"tokenizer——常见的多字符序列会被表示成一个token,罕见序列则用多个token表示。GPT-2的做法是先用词级预分词切成段,再对每段内部跑BPE(这门课的作业也是这么做)。

**1:12:43–1:16:07 BPE算法逐步演示("cat"/"hat"示例)**
把字符串转成字节序列,反复"合并出现频率最高的相邻token对":统计所有相邻pair出现次数→选出现最多的一对合并成一个新token(词表从256开始往上扩)→在整个训练序列里替换掉→重复这个过程。序列长度会随着合并逐渐缩短,压缩率随之提升。

**1:16:07–1:17:11 Encode/Decode演示**
编码时把字符串转成字节后,按BPE训练时记录的合并顺序依次重放合并操作。提到当前实现效率不高(比如encode遍历了所有merge规则,其实只该遍历用得上的),作业要求做到更高效,可以考虑并行化。

**1:17:11–1:17:49 总结**
Tokenizer在字符串和整数序列间转换。字符级、字节级、词级各有明显缺陷。BPE这个1994年的老算法,靠统计原始语料中的组合规律,依然是目前最有效的启发式方案。

**1:17:49–结尾**
如果未来架构能直接处理字节输入,也许就不需要再讲tokenization这一课了,但目前还得处理它。下节课预告:深入PyTorch细节,重点讲资源核算(FLOPs都花在哪了)。

## 一句话总结

这一讲的核心不是某个具体技术点,而是一个贯穿全课程的心法:在算力和数据都有限的前提下,"效率"是唯一真正重要的设计准则——从tokenizer选型、模型架构、训练策略到数据处理和对齐,每一个决策背后都是同一个问题:怎么用最少的资源换到最好的模型。后半段深入讲的BPE tokenization,本身就是"效率优先"这条主线的第一个具体案例:字符级/字节级/词级三种朴素方案分别在词表效率、序列长度、泛化能力上失败,BPE靠统计原始语料的组合频率,在这三者之间找到了一个实用的平衡点。
